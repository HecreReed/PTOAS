# 总分汇总规则

本文件定义 PTOAS 易用性评估的总分汇总方法。分项定义、量化指标、打分规则与 VOD 备注以 `ptoas-usability-scorecard-10pt.csv` 为准；本文件只负责说明如何把这些 `10 分制` 分项汇总成场景分和总分，并确保 `未实测` / `N/A` 不会被误当成低分。

## 1. 基本原则

- 单项、场景分、总分全部使用 `10 分制`。
- 场景分和总分默认按“已评分指标的简单平均”计算；用户明确指定权重时，再按用户权重计算。
- 场景分只基于本次选中的 `Core/Conditional Touch-Points` 或其 repo 级代理指标计算。
- 默认输出两个总分：
  - `总分（支撑）`
  - `总分（实测）`

## 2. 特殊值处理

- `未实测`：不计入任何总分分母
- `N/A`：不计入任何总分分母
- 如果某个场景下所有指标都是 `未实测/N/A`：
  - 该场景分不输出数值
  - 标记为 `本次无实测样本`

## 3. 场景分

先算场景分，再算总分。

### 3.1 场景支撑分

定义：该场景下所有“已评分”的指标，按 `10 分制` 直接求平均。

纳入范围：
- 文档
- 样例
- 脚本
- 配置
- 已实测项

排除范围：
- `未实测`
- `N/A`

用途：衡量 PTOAS 仓库本身提供的支撑能力。

### 3.2 场景实测分

定义：该场景下所有“有真实执行证据”的指标，按 `10 分制` 直接求平均。

必须满足至少一种证据：
- 真实命令执行
- 真实编译/build
- 真实 sample 运行
- 真实 validation / compare / board 结果

不纳入：
- 纯文档发现性分
- 纯 README/脚本存在性分
- `未实测`
- `N/A`

用途：衡量当前会话里真正被跑通或被验证到的易用性。

## 4. 默认场景权重

如果用户没有单独指定权重，默认用：

- `01`：`40%`
- `02`：`15%`
- `04`：`15%`
- `05`：`15%`
- `06`：`15%`

说明：
- `01` 是 PTOAS 的主评估场景，所以权重最高。
- `02/04/05/06` 是补充场景，默认均分剩余权重。

## 5. 权重重分配

不要把没有参与本次评估的场景硬算进总分。

### 5.1 用户只评部分场景

如果本次只评了部分场景，例如只评 `01 + 04`：
- 先取这两个场景的默认权重 `40` 和 `15`
- 再重分配到 `100%`

例：
- `01` 新权重 = `40 / (40+15) = 72.73%`
- `04` 新权重 = `15 / (40+15) = 27.27%`

### 5.2 计算 `总分（支撑）`

- 只保留“有场景支撑分”的场景
- 对这些场景的默认权重重分配后加权平均

### 5.3 计算 `总分（实测）`

- 只保留“有场景实测分”的场景
- 对这些场景的默认权重重分配后加权平均

## 6. 输出要求

建议固定输出以下内容：

- `总分（支撑）`：`x.x/10`
- `总分（实测）`：`x.x/10` 或 `本次无法计算`
- `覆盖场景`：本次实际评了哪些场景
- `覆盖层级`：`L1/L2/L3/L4` 到了哪一层
- `已选 Touch-Points`：本次到底用了哪些 `Touch-Point001~030`
- `实测覆盖说明`：哪些场景只有文档分，哪些场景有真实执行分

## 7. 解释口径

当两个总分差异较大时，优先按下面口径解释：

- `总分（支撑）` 高、`总分（实测）` 低：
  - 仓库文档/样例/脚本铺得比较全
  - 但当前会话真实跑通度一般，或存在环境/样例摩擦

- `总分（支撑）` 低、`总分（实测）` 高：
  - 当前 case 可能能跑
  - 但仓库的通用文档化、模板化、可发现性较弱

- `总分（实测）` 显示为 `本次无法计算`：
  - 说明本次基本停留在 `L1`，或者只有文档审阅，没有足够的真实执行证据

## 8. 推荐展示格式

```text
总分（支撑）: 7.9/10
总分（实测）: 6.6/10
覆盖场景: 01, 02, 04, 05, 06
覆盖层级: L1 + L2
已选 Touch-Points: Touch-Point001-011, 014-016, 024-030
说明:
- 01/04 同时形成支撑分和实测分
- 02/05/06 当前主要形成文档/样例支撑分
- L3/L4 未实测，不计入实测总分分母
```
